# 求职交付材料：PromptOps Studio

## 项目简介

一个本地 AI Agent 评测与测试开发工具练习项目。用 38 条原创合成用例驱动确定性 Mock Harness；另配套订单/退款模拟 API、业务集成测试、Prometheus 指标/告警演练、稳定性运行器和 k6 阶梯负载。v0.2.0 另有 40 条合成退款规则评测草案；其中 24 条 development case 已对两个 DeepSeek 路由各执行一次，共 48 个唯一组合、51 次请求尝试、43 组匹配草案断言、5 组未匹配。Gold 仍待人工审批，Provider 未返回费用，`benchmark_eligible=false`；不能写模型准确率或排名。订单 API 不是外部公司的真实生产系统。

## 常见追问

### 为什么先构建 Mock Harness？

先验证执行器、断言、Trace、报告和 UI 能正确工作，避免模型采样波动掩盖 Harness 自身的错误。Mock 不是通用 Agent，也不能作为模型基准。

### 执行成功但测试失败是什么意思？

execution_status=success 表示用例被执行并得到可检查的输出；case_status=failed 表示输出不符合预期。agent-014 是实例：Mock 正常返回了 web_search 调用，但测试要求 weather_lookup。

### 如何覆盖工具错误？

数据集对 timeout、exception、invalid_output 和业务拒绝做确定性 Mock 注入。它们验证错误分类、任务状态和失败归因，不通过访问网络或等待真的工具超时。

### 如何保证可重复？

固定数据、确定性 Mock 路由、无随机抽样和本地工具 Stub。重复运行会有不同 Run ID、时间与 Trace 事件标识，但同一 case 的行为输出应一致。

### Trace 是什么？

按执行顺序记录输入、工具选择、参数检查、工具调用、返回、最终输出、断言与完成事件。内容只包含可观察数据；不把它描述为模型思维链。

### 为什么保存完整报告快照？

报告固化了当次数据集、输入、断言、Agent 输出和配置元数据。详情、历史和导出读取同一份快照，避免日后修改数据定义导致旧报告被重算。

### 真实 Provider 有什么保护？

默认 Mock。Provider 只能由用户显式选择；需要服务端 Base URL、模型名和环境变量凭证。实现了超时、有限重试、HTTP 错误分类、JSON/结构校验和敏感字段脱敏；测试使用本地 HTTP Stub。没有凭证时会在外部请求前拒绝。

### 回归比较是否等于 Prompt V1/V2 对比？

不是。当前比较两个已保存运行，并依据数据集、运行时指纹和标签判断比较语义。Prompt/Agent 版本框只是元数据标签，没有连接不同 Prompt 文件或 Agent 实现，因此只改标签不能证明真实版本差异。

### 旧报告显示 92.31% 通过意味着什么？

这是数据集 1.0.2 下历史 Mock 运行 24/26 通过的结果。agent-014 与 agent-015 持续失败，质量门禁失败。该比例不代表 1.1.0 或真实模型准确率，也不代表统计显著性。

### 为什么不使用异步队列？

当前是 38 条 Mock 用例的本地同步执行，暂未达到队列和多 Worker 的需求。UI 忙碌状态对应 HTTP 请求生命周期，不展示伪造进度。更大测试集可再增加队列、取消、重试和并发控制。

### 尚缺什么？

真实模型运行样本、动态 Prompt/Agent 版本绑定、异步调度、并发/预算管理、用户权限、多租户、生产审计与部署。本地 H2 适合演示，不代表多用户生产数据库。
